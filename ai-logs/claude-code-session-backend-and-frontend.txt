  Structure

  backend/
  ├── server.js                         # entry: connects Mongo + Redis, then 
  listens
  ├── app.js                            # Express app: helmet, cors, morgan, 
  express.json()
  ├── config/
  │   ├── env.js                        # loads the root .env and checks 
  required variables
  │   ├── database.js                   # connectDb / disconnectDb / isDbReady
  │   └── redis.js                      # shared redisClient, connectRedis / 
  disconnectRedis / isRedisReady
  ├── controllers/health.controller.js
  ├── routes/health.routes.js           # GET /healthz
  ├── middleware/error.middleware.js    # 404 + error handler
  ├── models/ services/ workers/ utils/ # empty for now (.gitkeep)
  └── package.json

  - Environment: config/env.js reads starter/.env, the root one. Values already
    set in the environment take priority, so the check can choose its own PORT.
  - ES modules: everything uses import/export ("type": "module") and plain
    JavaScript.
  - Startup order: MongoDB and Redis connect in parallel. The server only starts
    listening if both succeed. If either fails, it closes the other connection
    and exits.
  - Redis: on startup it gives up after 5 retries so a bad URL fails quickly.
    Once connected, it reconnects automatically if the connection drops later.
  - /healthz: returns 200 only when both MongoDB and Redis are connected (the
    brief requires 200 once the server is ready), otherwise 503. Example: { ok, 
    mongo: "up"|"down", redis: "up"|"down", uptime }.
  - Shutdown: Ctrl+C closes the server and both connections cleanly.
  - Your existing files: I rewrote your database.js and redis.js, keeping the
    same idea. package.json keeps all your dependencies, including ws.
  - New .env: I copied .env.example to .env in the root, since there wasn't one.

  How to run

  # 1. Start Docker Desktop, then from starter/ :
  npm run up          # MongoDB, Redis and the simulators
  npm run doctor      # confirms the ports are reachable

  # 2. Start the backend
  cd backend
  npm install         # already done, only needed on a fresh clone
  npm run dev         # nodemon, restarts on changes   (or: npm start)

  # 3. Check it
  curl http://localhost:4000/healthz

  If it works, you'll see MongoDB connected, Redis connected and Server 
  listening on http://localhost:4000.

  Before you run npm run check: switchboard.json still points at the scaffold
  (npm --prefix scaffold/server start). If you're using this backend instead,
  change it to:

  { "install": "npm --prefix backend install", "start": "npm --prefix backend 
  start", "health": "/healthz" }

  How the endpoint behaves

  POST /__grader/claim with body { workspace, contact, agent }:

  ┌─────────────────────────────────────────┬───────────────────────────────┐
  │                Situation                │            Status             │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │ This agent now holds the conversation   │ 200 with { conversationId,    │
  │ (newly claimed, or claimed again by the │ workspace, contact, assignee  │
  │  holder)                                │ }                             │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │ Another agent holds it                  │ 409, same fields plus error;  │
  │                                         │ the holder is unchanged       │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │ Missing, empty or non-string field, or  │ 400                           │
  │ malformed JSON                          │                               │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │ Unknown workspace                       │ 404, and nothing is created   │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │ Missing or wrong x-grader-token         │ 401                           │
  ├─────────────────────────────────────────┼───────────────────────────────┤
  │                                         │ the claim creates the         │
  │ Contact has never written               │ conversation, as BRIEF.md     │
  │                                         │ requires                      │
  └─────────────────────────────────────────┴───────────────────────────────┘

  Why only one agent can win:
  1. The conversation is upserted on {workspaceId, contact}, and a unique index
     on that pair stops two simultaneous claims from creating two copies.
  2. A single findOneAndUpdate sets the agent, and it only matches if the
     conversation is unassigned or already held by that agent. MongoDB applies
     that atomically, so only one request can win.

  Every query includes workspaceId. This also holds with several server copies
  running.
